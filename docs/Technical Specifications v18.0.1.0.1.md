### **1\. Version 18.0.1.0.1 Overview**

This version introduces powerful new "Agent-based" functionalities, moving beyond simple translation to proactive content strategy and creation. The core focus is on two new AI agents: a **Content Research Agent** to generate topic ideas and a **Content Generation Agent** to draft blog articles. Additionally, this version will implement a dashboard for monitoring OpenAI API usage and costs.

A key architectural change will be the consolidation of all module settings into a dedicated section within the Odoo settings for better organization and usability.

### **2\. Refactoring: Centralized Module Settings**

To improve maintainability, all existing and new configuration settings will be moved from "General Settings" to a dedicated page.

* **Location:** Settings \> Marketing Automation  
* **Implementation:**  
  * Create a new res.config.settings view.  
  * Create a new menu item in Settings that opens this view using a dedicated action.  
  * Migrate existing OpenAI fields (sc\_openai\_api\_key, sc\_openai\_organization\_id) to this new view.  
  * All new settings defined in this document will be added to this dedicated page, organized into sections for each agent.

### **3\. Feature A: Content Research Agent**

This agent uses the WebSearchTool from the OpenAI Agents SDK to find recent articles and news online, providing structured content ideas.

#### **3.1. New Data Models**

**a) sc.content.idea (Main Model)**

* **Description:** Stores a single content idea generated by the research agent.  
* **Fields:**  
  * name (Char, required): The title of the source article/news.  
  * url (Char, required): The full URL to the source.  
  * publish\_date (Date): The publication date of the source article.  
  * summary (Text, required): A concise summary generated by the agent.  
  * task\_id (Many2one, sc.content.idea.task): Link to the generation task.

**b) sc.content.idea.task (Task Tracking Model)**

* **Description:** Tracks the status of each content idea generation request.  
* **Fields:**  
  * name (Char, required, default="Content Idea Task"): Descriptive name.  
  * search\_query (Text): The final search query/prompt used.  
  * requested\_ideas (Integer): The number of ideas the user requested.  
  * generated\_ideas\_ids (One2many, sc.content.idea): The ideas created by this task.  
  * state (Selection, required, default='draft'): draft, in\_progress, done, error.  
  * error\_message (Text): Stores error details.

#### **3.2. Configuration (in Settings \> Marketing Automation)**

* **Section:** Content Research Agent  
* **Fields:**  
  * sc\_research\_agent\_model (Selection, dynamic): The OpenAI model for this agent (e.g., gpt-4o). The selection list should be populated dynamically via the API, with a fallback list.  
  * sc\_research\_agent\_instructions (Text): The "system instructions" for the agent. This field should have a default value based on the example script provided.  
  * sc\_research\_agent\_default\_query (Text): The default "search\_query" that will populate the wizard. This field should also have a default value.

#### **3.3. User Workflow & UI**

1. **Menu Items:**  
   * Marketing Automation \> Content Ideas \> All Ideas (Tree/Form view for sc.content.idea).  
   * Marketing Automation \> Content Ideas \> Generation Tasks (Tree/Form view for sc.content.idea.task).  
2. **Generate Ideas Wizard:**  
   * An "Action" button on the sc.content.idea tree view named "Generate Content Ideas" opens a wizard.  
   * **Wizard Model:** sc.generate.ideas.wizard (TransientModel).  
   * **Wizard** View **Fields:**  
     * search\_query (Text, required): Pre-filled from sc\_research\_agent\_default\_query, but editable by the user.  
     * number\_of\_suggestions (Integer, required, default=5): How many ideas to generate.  
   * **Action:** Clicking "Generate" creates a new sc.content.idea.task record and sets its state to draft.

#### **3.4. Backend Logic (Cron Job)**

* A new ir.cron job will run periodically to process sc.content.idea.task records in the draft state.  
* **For each task:**  
  1. **Set State:** Change state to in\_progress.  
  2. **Process Placeholders:** Before sending to the AI, process placeholders in the search\_query.  
     * {today} should be replaced with the current date (e.g., YYYY-MM-DD).  
  3. **Execute AI Call:**  
     * Use the openai-agents SDK. The agent must be initialized with the WebSearchTool.  
     * **CRITICAL:** The agent's output\_type must be configured to expect a structured response (a list of articles), similar to the Pydantic models in the example. The Odoo implementation must define corresponding Python classes (e.g., using dataclasses) to help the agent structure its output as a clean JSON list.  
  4. **Process Response:**  
     * **On Success:** The cron job will parse the JSON list returned by the agent. For each item in the list, it will create a new sc.content.idea record and link it to the task. Finally, set the task state to done.  
     * **On Failure:** Log the error, set the task state to error, and populate error\_message.

### **4\. Feature B: Content Generation Agent**

This agent takes a sc.content.idea and a user prompt to generate a complete draft for a blog.post.

#### **4.1. New Data Models**

**a) sc.content.generation.task (Task Tracking Model)**

* **Description:** Tracks the status of each blog post generation request.  
* **Fields:**  
  * name (Char, required): e.g., "Blog post generation for: \[Idea Title\]".  
  * content\_idea\_id (Many2one, sc.content.idea): The source idea.  
  * user\_prompt (Text): Additional instructions from the user.  
  * generated\_blog\_post\_id (Many2one, blog.post): The resulting blog post.  
  * target\_blog\_id (Many2one, blog.blog): The blog to post in.  
  * target\_author\_id (Many2one, res.partner): The post author.  
  * target\_lang\_id (Many2one, res.lang): The language of the article.  
  * state (Selection, required, default='draft'): draft, in\_progress, done, error.  
  * error\_message (Text): Stores error details.

#### **4.2. Configuration (in Settings \> Marketing Automation)**

* **Section:** Content Generation Agent  
* **Fields:**  
  * sc\_generation\_agent\_model (Selection, dynamic): Model for this agent.  
  * sc\_generation\_agent\_instructions (Text): System instructions for the blog post writer agent. Should instruct the agent to generate content, a title, meta description, and keywords.

#### **4.3. User Workflow & UI**

1. **Menu Item:**  
   * Marketing Automation \> Content Generation \> Generation Tasks (Tree/Form view for sc.content.generation.task).  
2. **Generate Content Wizard:**  
   * A new button "Generate Content" will be added to the blog.post tree view header.  
   * **Wizard Model:** sc.generate.content.wizard (TransientModel).  
   * **Wizard View Fields:**  
     * content\_idea\_id (Many2one, sc.content.idea, required): User selects from the list of generated ideas.  
     * user\_prompt (Text): Optional field for specific instructions.  
     * blog\_id (Many2one, blog.blog, required): The target blog.  
     * author\_id (Many2one, res.partner): The author of the post.  
     * lang\_id (Many2one, res.lang, required): The language for the article.  
   * **Action:** Clicking "Generate" creates a sc.content.generation.task record.

#### **4.4. Backend Logic (Cron Job)**

* A new ir.cron job processes sc.content.generation.task records.  
* **For each task:**  
  1. **Set State:** in\_progress.  
  2. **Build Prompt:** Combine the agent's system instructions, the summary from the content\_idea\_id, the user\_prompt, and specific instructions to generate a title, HTML content, meta description, and keywords in a structured JSON format.  
  3. **Execute AI Call:** Call the OpenAI agent, expecting a JSON object as a response.  
  4. **Process Response:**  
     * **On Success:** Parse the JSON. Create a new blog.post record with the received data. **IMPORTANT:** The new post must be created with is\_published \= False. Link the new post to the task and set the task state to done.  
     * **On Failure:** Set task state to error and save the error message.

### **5\. Feature C: OpenAI Usage Statistics**

This feature provides a view of API token consumption associated with the configured API key.

#### **5.1. API Research & Data Model**

* **Developer Task:** The development team must research the official OpenAI API documentation for "Usage Monitoring". The goal is to find an endpoint that provides daily usage data (prompt tokens, completion tokens, total tokens). This is typically a protected endpoint that requires the API key.  
* **New Model:** sc.openai.usage.snapshot  
  * **Description:** Stores a daily snapshot of OpenAI API usage.  
  * **Fields:**  
    * date (Date, required, unique): The day of the usage data.  
    * prompt\_tokens (Integer): Total prompt tokens for that day.  
    * completion\_tokens (Integer): Total completion tokens for that day.  
    * total\_tokens (Integer): Sum of prompt and completion tokens.

#### **5.2. UI & Backend Logic**

1. **Menu Item:**  
   * Marketing Automation \> OpenAI Usage  
2. **View:**  
   * The action for the menu item will open a custom view (e.g., a form view on res.config.settings or a dedicated dashboard model).  
   * **Components:**  
     * A "Fetch Latest Data" button.  
     * A graph showing total\_tokens over the last 30 days.  
     * A tree view listing the sc.openai.usage.snapshot records.  
3. **Backend Logic:**  
   * A method triggered by the "Fetch Latest Data" button will make an authenticated call to the OpenAI Usage API.
